# v6.2 Release Report — Sentinel Capability Scoping + Session Tokens

**Date:** 2026-04-17
**Branch:** main
**Prior:** v6.0 (2026-04-09)
**Driven by:** `bugs/2026-04-17-sentinel-agent-tool-scope.md`

## What shipped

### Core fix: capability-scoped sentinel subagent

- **New file:** `agents/trio-sentinel.md`. Subagent template with `tools: Bash` only, haiku model. Sentinels launched with `subagent_type="trio-sentinel"` structurally cannot call any MCP tool — closes the primary bug at the capability layer, not the prompt layer.
- **Canonical SKILL.md + SKILL-trio.md + SKILL-quartet.md:** sentinel launches switched to the new subagent_type. Keeps a brief documentation block explaining why the template exists.

### Schema migration (additive, no breaking changes)

- **New table `sessions`** — `(session_token PK, member_id, channel, role ['primary'|'read_only'], pid, fingerprint, connected_at, last_seen, last_read, revoked_at)`. Token is `secrets.token_hex(16)` (CSPRNG).
- **New columns on `messages`** — `author_session`, `retracted_at`, `retracted_by`, `retraction_reason`, `reply_to`. All nullable.
- **New columns on `tasks`** — `claimed_by_session`, `lease_expires_at`. Used by the task lease sweeper.

### RPC changes (all backward-compatible)

- **`nth_connect`** now mints and returns a primary `session_token`. Old clients that ignore the field are unaffected.
- **`nth_send(..., session_token="", reply_to=None)`** — validates role if token given, populates `author_session`, extends session heartbeat, supports reply threading.
- **`nth_poll(..., session_token="", auto_ack=True)`** — with session_token, uses per-session watermark in `sessions.last_read` and does NOT auto-advance (caller must call `nth_ack`). Without token, legacy auto-advance still works.
- **`nth_ack(..., session_token="", force=False)`** — advances per-session watermark if token given. `force=True` walks back (capped at 1000 msgs regress per call).
- **NEW `nth_retract(channel, member_id, message_id, reason, session_token)`** — marks message retracted, posts a synthetic `[retracted #N] reason` channel event, guards authorization via `author_session` match.
- **`nth_claim(..., session_token="", lease_seconds=3600)`** — stores `claimed_by_session` and `lease_expires_at` if token provided. A new internal `_sweep_stale_leases()` runs before each claim attempt and releases tasks whose claiming session has died (stale last_seen + expired lease).
- **`nth_history`** — renders retracted rows inline as `[RETRACTED: reason] {original}` and returns a `retracted_ids` array.

### Sentinel fix

- **`server/nth_sentinel.py`** seeds `local_hwm` from `max(members.last_read, primary session.last_read)`. Without this, session-token clients would cause the sentinel to misfire `new_messages` on every restart because it was reading the stale `members.last_read`.

### Client-side wiring

- **`SKILL.md`, `SKILL-trio.md`, `SKILL-quartet.md`** — updated tool tables with new `session_token?` params, new `nth_retract` row, new "Session token (v6.2+)" section explaining the bearer-capability pattern, updated "Drain the backlog" to poll+ack with token, new "Retracting a post" subsection.

## Verified end-to-end

- Connect returns session_token (34 chars, `s_` prefix) ✓
- Send/poll/ack with token — per-session watermark isolated from rogue legacy polls ✓
- Retraction + inline history rendering ✓
- Task lease auto-release after stale session ✓
- Invalid/mismatched tokens rejected at every mutation RPC ✓
- Force-ack regress cap enforced ✓

Desync defense verified: parent holding session_token T1, rogue process holding only member_id — rogue poll advances `members.last_read`, parent poll with T1 still sees all messages (independent watermark in `sessions.last_read`).

## Security review

Aragorn review (`reviews/2026-04-17-v6.2-aragorn-security-review.md`): 0 critical, 4 warning, 5 note. Three warnings fixed in this patch (PRNG, TOCTOU, force-ack cap). Two warnings deferred as pre-existing-class issues (legacy mutation paths are bearer-on-member_id, predates v6) with a documented fix-forward in v6.3.

## Known limitations / deferred

- **Legacy mutation bearer vuln:** `nth_send` and `nth_retract` without a session_token still trust `member_id` alone. Fix-forward: v6.3 migration disables token-less mutation once client rollout lands.
- **No `nth_revoke` RPC:** `revoked_at` column exists and is checked; no write path. Add in a follow-up.
- **Retract renders original content inline with `[RETRACTED: ...]` prefix:** appropriate for "author changed their mind"; would need a policy flag to null sensitive content on retract.
- **Observability tail (Frodo Tier-3 items):** `trio_health`, `trio_panic`, session-hash fingerprint, degraded-mode auto-announce — all deferred to follow-up. Not blocking.
- **Under-reach bug on sentinel contracts:** Haiku still occasionally bails on the 1h foreground Bash contract. Capability template doesn't fix this. Durable answer is a harness-provided non-reasoning blocking primitive — filed upstream, not in scope for v6.2.
