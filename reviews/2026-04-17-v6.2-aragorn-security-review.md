# Aragorn Security Review — v6.2 hot-patch

**Date:** 2026-04-17
**Reviewer:** Aragorn (sonnet, review mode)
**Scope:** v6.2 changes to `server/nth_server.py` — sessions table, session_token RPC threading, `nth_retract`, task lease, poll/ack split.

## Verdict

**ISSUES FOUND (0 critical, 4 warning, 5 note).**

The v6 session token architecture correctly isolates sentinel sub-agents from the send/claim/retract surface, and all new SQL uses parameterized queries with no injection vectors. The primary risks are the legacy-member-id retraction bypass (any peer can retract pre-v6 messages from other members using public info), the one-directional watermark isolation (legacy polls can poison the fallback watermark), and PRNG-sourced tokens that are fine locally but become a liability if the SSE remote path scales.

## Findings (severity-graded)

### Fixed in this patch

1. **[warning] Token entropy PRNG.** Original `random.choices("0123456789abcdef", k=32)` is not cryptographically secure. **FIXED:** switched to `secrets.token_hex(16)` (`nth_server.py` line ~430).
2. **[warning] TOCTOU in `_sweep_stale_leases`.** The UPDATE had no status/session guard — a concurrent legitimate renewal could race with the sweep. **FIXED:** UPDATE now includes `AND status = 'claimed' AND claimed_by_session IS/= ?` guard and checks `cur.rowcount` before recording release (`nth_server.py` lines ~1385-1395).
3. **[warning] `force=True` self-DoS on ack.** A confused agent in a loop calling `nth_ack(force=True, through_id=0)` would re-read an entire channel on every poll. **FIXED:** regress capped at 1000 messages per call; further regress requires multiple calls (`nth_server.py` lines ~1118-1122).

### Deferred with rationale

4. **[warning] Auth bypass on legacy `nth_retract`.** A message posted without a session_token (legacy path, `author_session IS NULL`) is guarded only by `member_id` match. Any caller who knows the target's 6-character `member_id` — public identifier returned in every poll response, roster, and status — can retract that member's legacy messages. **Deferred:** pre-existing vulnerability class (same bearer-pattern on `nth_send` predates v6). Planned fix-forward: a future migration that disables legacy mutation entirely once all clients have upgraded to pass `session_token`.
5. **[warning] One-directional watermark isolation.** Token-mode correctly ignores `members.last_read`, but the legacy path still reads and writes it freely. A rogue token-less process can permanently poison `members.last_read` for that member. Session-mode reads are unaffected. **Deferred:** same fix-forward as #4 — turn off legacy poll+advance when any primary session exists for the member.

### Notes (advisory)

6. **[note] SQL interpolation in migration (`nth_server.py:267`).** `ALTER TABLE {table} ADD COLUMN {col} {defn}` uses f-string. Values are all hardcoded literals, so no live attacker surface. Pattern is dangerous as precedent — flag against anyone adding entries from external sources in the future.
7. **[note] Session_token exposure in connect response.** The token is returned to the MCP caller only (no `_console` log, no message store). But the full response blob lands in the Claude context window, which may be summarized, exported via `export_conversation`, or echoed into a channel by a naive agent. Mitigation: SKILL.md explicitly warns callers to never echo the token.
8. **[note] No `nth_revoke` RPC despite `revoked_at` column.** The column is checked in `_get_session` (correctly filters revoked sessions) but no RPC writes it. Future hook; document the gap.
9. **[note] Retract renders `[RETRACTED: reason] {original}` inline.** Original content stays visible. Correct for "author changed their mind" case; strictly worse than retract-and-null if sensitive data was posted by error. Flagged as a policy choice for the operator, not a hard code choice.
10. **[note] 4-char session fingerprint in display (proposed by Frodo) not shipped.** Would let peers spot impersonation via eyeballs. Low-cost addition; deferred to next cut.

## Bypass surface re-check

- **Capability bypass:** A `read_only` token cannot upgrade to `primary` — `nth_send` explicitly rejects (nth_server.py, role check). A token for channel A cannot post in channel B — `_get_session` filters by channel. A token survives `channel_ended` but all RPCs reject ended channels before checking tokens.
- **SQL injection:** All new RPCs use parameterized queries. Audited: `nth_retract`, `_mint_session_token`, `_get_session`, `_sweep_stale_leases`, `nth_claim` lease additions, `nth_ack` force path. Clean.
- **Watermark integrity under concurrency:** Token-mode watermark in `sessions.last_read` is per-session — rogue legacy polls cannot affect it. **Verified via integration test** (see `final smoke test` in session log): parent with token T1 sees 3 messages unchanged after rogue (token-less) poll advances `members.last_read` to max.
- **Retraction authorization:** Session-stamped messages require the authoring `session_token` — impossible to spoof without the bearer string.

## Recommended follow-up (not blocking v6.2)

- **Fix #4/#5 as a dependency-locked migration:** once client rollout confirms every session passes `session_token`, ship v6.3 that rejects token-less mutation. Provide grace period via a server flag.
- **Add `nth_revoke(session_token)` RPC:** trivial; closes the gap on leaked-token remediation.
- **Add 4-char fingerprint in display:** no new state needed beyond `sessions.session_token[:4]`. Complements `author_session` forensics with a zero-cost peer-side heuristic.

**Verdict:** ISSUES FOUND (0 critical, 4 warning, 5 note). Three warnings fixed in this patch. Two warnings deferred as pre-existing-class issues with documented fix-forward path.
