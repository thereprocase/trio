## Joint diagnosis

All four reviewers converged on the same root framing: `member_id` is an ambient bearer token. Any process that saw the prompt is as authoritative as the parent. `trio_poll` auto-advances the shared watermark on read, which is what makes the bug self-hiding (rogue consumes unread, parent sees `no_new`). The sentinel-as-sub-agent architecture is separately fragile: Haiku can't hold the contract reliably in either direction (over-reach or under-reach).

## Architectural insight — Gandalf correction

Initial Gandalf finding "the sub-agent is a reasoning construct misused as a supervisor" missed the economic shape of the system. User clarified:

> You cannot inject data into a claude. It must ask. It can have a model return. Tool calls have time limits. Using Opus to reset tool calls is fucking bonkers expensive. Enter: haiku. trio must be capable of keeping an opus agent 'on hold' for 10+ hours virtually for free.

The sentinel is a **pull-to-push adapter / tool-call-time-limit extender**. The Opus parent is reasoning-expensive; the sentinel's Haiku-priced blocking Bash call is the cheap proxy that surfaces external events. Replacing it with an OS daemon loses the wake mechanism — the parent still has to poll at Opus rates, which is the whole thing the architecture is avoiding.

Gandalf's #5 withdrawn. Under-reach (Haiku bailing on the 1h contract) stays a live concern but the durable answer is a harness-provided non-reasoning blocking primitive (a tool, not an agent), not an OS daemon.

## Durable fix shape (post-correction)

1. **Ship:** #2 (poll/ack split) + #3 (author_session) + #4 (sessions table keystone) + #6 (trio-sentinel subagent template) + #7 (nth_retract).
2. **File upstream:** harness feature request for subagent templates with pinned tool allowlist AND a non-reasoning blocking-tool primitive. Trio is first customer, not last.
3. **Tier 1 prompt deny-list stays** until #6 is universally deployed — costs nothing, works today.

## Conflicts resolved

- **Gandalf vs. rest on architecture:** Gandalf's OS-daemon proposal lost on the economic argument. Sub-agents stay, capability-scoped.
- **Aragorn derived sentinel ID (#15) vs. Sauron session token (#4):** Same problem, two solutions. Session token wins — cleaner at the server, no display-filter problem for peers.
- **Over-reach vs. under-reach as one bug:** Distinct. Capability scoping fixes over-reach; under-reach needs different fix (model pin or non-reasoning executor). Flagged separately.
