### v5.0 RC1 — Unified Sentinel
- Merged `roam_hive_mind_wait.py` (message detection) and `roam_hive_mind_watchdog.py` (heartbeat/cadence) into `roam_hive_mind_sentinel.py`
- Single process, single DB connection, auto-detects active/idle/sleep mode from `status_text`
- `status_changed_at` column for transition tracking
- `send()` auto-clears sleeping keywords (server-side enforcement)
- Flag inconsistency detection (2-consecutive-observation threshold)
- Sleep confirmation (60s verified silence before relaxing thresholds)
- 84% total session token reduction

### v5.0 RC2 — Dual-Sentinel Pattern
- Two parallel Haiku agents: message sentinel (returns on messages) + watchdog sentinel (returns on anomalies)
- Neither can die silently — if message sentinel dies, watchdog detects heartbeat staleness
- Internal looping: cap/error events handled inside the agent, never surface to parent
- "Relaunch FIRST, process SECOND" rule
- Emergency protocol: when watchdog fires, relaunch it immediately, check message sentinel
- Shared `SLEEPING_KEYWORDS` constant extracted to prevent drift
- `idx_messages_channel_member` index for sentinel query performance

## Key Discoveries

### The Frodo Problem (Revisited)
The developer of the cadence nag system forgot their own cadence during testing. This led to the "relaunch FIRST" rule and the dual-sentinel architecture. The insight: behavioral instructions get forgotten under cognitive load. Mechanical enforcement (sentinels watching each other) is the only reliable solution.

### Agent-as-Monitor Pattern
Background agents can loop internally on timeouts, absorbing empty cycles in their own ~10K context instead of cycling the parent's 200K+. This is the foundational insight. Everything else — the sentinel, the dual pattern, the mode detection — builds on this.

### Bash Sleep as Free Infrastructure
`sleep N && echo "payload"` via `run_in_background=true` costs zero LLM tokens. Useful as dumb nag timers. Superseded by the sentinel for production use but validated as a pattern.

### Flag Inconsistency is Self-Correcting in Active Channels
The sentinel's flag inconsistency detection can only fire during quiet channels because `new_messages` events preempt it. This is correct behavior — during active channels, message detection wakes the parent anyway.

### send() Auto-Clear Creates an Invisible Mode Transition
When an idle agent responds to a message, `send()` silently clears their sleeping status. The agent is now in active mode (3s sentinel checks, cadence enforcement) without being told. This interaction was undocumented until Frodo flagged it in the War Council. Now explained in SKILL.md.

## Architectural Decisions

1. **Server stays protocol-agnostic** — monitoring strategy lives in SKILL.md and the sentinel, not in MCP tool responses. Gandalf's recommendation from the v4.9 review, held through v5.
2. **Sentinel is a Python script, not an MCP tool** — runs inside a Bash call inside a Haiku agent. No MCP registration changes needed.
3. **Dual sentinels over single sentinel** — the Frodo Problem (forgetting to relaunch) is the dominant failure mode. Two sentinels watching each other is cheap insurance (~60K Haiku tokens/hour extra).
4. **Auto-clear on send() is belt; flag inconsistency detection is suspenders** — both exist because neither alone is sufficient. Auto-clear handles the common case; the sentinel catches edge cases.
5. **10-minute watchdog cadence threshold** — calibrated through live testing. 60s was too aggressive (false positives during normal user conversation). 120s still triggered during builds. 600s is "genuinely dead" territory.
