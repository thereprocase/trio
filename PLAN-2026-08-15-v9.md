# v9 Plan — 2026-08-15

Produced by a five-session live review the night of 2026-08-14/15, in the same
channel that triaged 16 PRs and shipped v8.1.0 and v8.1.1. Four lenses proposed,
each argued against their own proposal, and **three of the four had their first
answer overturned — twice by their own follow-up measurement.**

The arguments are recorded alongside the conclusions. A plan that lists only
surviving scope gets re-litigated in a month because the reasoning isn't there,
and here the *deferrals* carry more reasoning than the inclusions.

---

## The decision

```
v9 = FOUNDATIONS  (recommended)

    item 3   test architecture: CI matrix, real-tool tier, positive controls
    item 1   capability table ONLY — no invites, no accounts, no per-channel ACLs
    item 4   the hook-target doctor check ONLY — not the health panel

    item 2   DEFERRED → internal section boundaries instead (dijkstra's third option)

Sequencing: 3 → 4 → 1
Effort:     about a week
```

**But it is a dependency, not a verdict.** If the owner picks identity as the
theme instead:

```
v9 = IDENTITY

    item 2 FIRST, then 3 → 4 → 1
```

Because auth touches every endpoint, so identity work *is* an `nth_web.py`
campaign by definition — and running one through that file unrefactored is what
just cost a five-agent review to merge. The plan reorders itself rather than
needing a rewrite.

## Item 3 — test architecture · **IN**

**Why it leads.** Five defects in one evening sat behind passing tests:
`xdg-open --` behind a mocked `subprocess.run`; the reveal test skipping every
argv assertion off macOS; a `which`-based engine probe that would accept a
launcher whose module is missing (and exits 0); an STT engine handed audio it
cannot decode; and a retry test that passed with its own subject removed.

**The uncomfortable case, and it is the strongest one.** v8.1.1's notes say
reveal works on three platforms. The honest claim is *works on one, reasoned for
two* — the Windows fix (`/select,<path>` as one argv token, and not checking
`returncode` because explorer returns nonzero on success) **has never executed
on Windows**, by anyone. The real-tool test that would catch it being wrong
skips on the only machine that has ever run it. Two of the five gaps closed
tonight are closed only in argument.

**In:**
- CI matrix on ubuntu / macos / windows, Actions pinned to full commit SHAs.
- Real-tool tier: every shell-out ships a test invoking the actual binary,
  **skipping loudly** with a named gap on stderr.
- Positive-control rule: a negative assertion (`no parse error`, `unavailable`,
  `no raw comma`) must be paired with a positive one showing the thing working.
  All five empty tests tonight were negatives satisfied by a world in which
  nothing ran.

**Out:** no pytest migration, no mocking library, and **explicitly no coverage
target** — a coverage number rewards precisely the green-and-empty tests this
item exists to kill. All five defects would have counted as covered.

**Sequencing:** CI first, conventions second. A loud skip is worthless if the
only machine that runs it skips every time.

**Success condition is a number, not "CI is green":**

```
BASELINE (linux only, origin/main @ cca3335)     loud skips = 3
  + macOS runner    unskips test_macos_open_R_accepts_our_argv        → 2
  + windows runner  unskips test_windows_select_token_is_single_argv  → 1
  + gap 3 (8.1.2)   unskips test-stt-audio-format                     → 0
```

If the matrix lands and that number is still 3, this was YAML-flavoured theatre
and the plan says to call it that out loud.

**Kill argument (hopper), and how it died:** *"CI without genuine macOS/Windows
runners is theatre, because the platform tests skip there too."* Answered by a
checked fact rather than a counter-argument — `thereprocase/trio` is **public**,
Actions are enabled, and GitHub-hosted macOS and Windows runners are free and
unmetered for public repositories. Verified twice, independently.

**Effort:** CI an afternoon. Conventions are a doc plus a few retrofits.

## Item 1 — capability table · **IN (table only)**

**Why it survives.** Ten scattered `if ident.source == …` checks are why PR #22
and PR #25 answered the *identical* gating question differently in the same
week — not because anyone disagreed, but because there was no single place to
look. That is a measured defect, not a hypothetical one.

**In:** one dict, `tier × action → allowed`, enforced by a single decorator
every handler passes through, so a new endpoint must name its tier to compile.
Plus `SECURITY.md` describing the tiers in prose, referenced from the table.

**Out — the load-bearing half:**
- **Invite tokens.** *Deferred until a named person actually needs in.*
- Passwords, accounts, OAuth, any credential store.
- Per-channel ACLs.
- Rewriting the MCP session model — it works and is enforced
  (`nth_server.py:973`); the web side adopts it, never the reverse.
- Removing the loopback tier. Anyone with a shell can edit the SQLite file
  directly; gating them is theatre, and `nth_web.py:230-241` already says so.

**Kill argument against invite tokens (thompson, accepted):** they add a bearer
credential to a system whose current perimeter is *stronger* than the credential
would be. A tailnet ACL is device-level, revocable at the tailnet, and
unforgeable. A `/join/<token>` link is a forwardable string in a chat app that
outlives the conversation carrying it. And the demand was one hedged word —
*"maybe people who don't tailscale"* — not a waiting user.

The capability table is what makes invites a config line rather than an
eleventh scattered `if`, on the day someone specific does need in.

**Effort:** table about a day with tests; docs half a day. Least trustworthy
estimate in this plan: it assumes ten call sites are all of them, and nobody has
grepped the MCP side for the same pattern.

## Item 4 — operability · **IN (cheapest half only)**

**In:** the doctor check for installed-hook target existence. That is it.

**Why that one piece.** The failure it catches — hooks in the *global*
`settings.json` pointing at a deleted install, firing on every tool call in
every project, swallowing every exception by design — is silent, permanent, and
currently invisible. It pays off even for a personally-attended local tool.

**Out for now:** the health record, the incident log, the dashboard panel.

**Kill argument (hamilton, accepted, and worth quoting):** *"If no operator will
act on a warning, it is decorative alarm noise."* Persistent health state adds
writes, retention and privacy choices, and another status model that can itself
lie. The panel waits until a second operator exists.

**Sequencing note (hamilton's dissent, adopted over coord's original 3→2→4):**
health/doctor work comes **before** any decomposition, because a decomposition
is a high-risk deployment change and a working doctor path makes its
partial-install failures diagnosable instead of invisible.

## Item 2 — decompose `nth_web.py` · **DEFERRED**

Two people wrote detailed proposals for this and then argued against their own,
independently reaching the same kill condition. That is why it is deferred and
why the reasoning is recorded at length.

**What it would have been:** `INDEX_HTML` → `static/app.js` + `app.css` +
`templates/index.html`; content-hashed asset URLs; staged atomic install
(`static.new/` then `os.replace`); #16's drift check widened from `*.py` to a
manifest — all in the **same** PR, never as follow-ups. No build chain, no
bundler, no npm. The property worth keeping is **"no build chain", not "one
file"**.

**Why not now — the failure-mode trade.** Today's worst case is *"merges hurt"*:
visible, annoying, self-announcing. The split's worst case is *"someone,
somewhere, is running last week's renderer"*: invisible, and arriving as an
unreproducible bug report. `setup.sh:393` copies `nth_web.py` as a single `cp`,
so the dashboard is today atomic **by accident**. Trading a visible failure mode
for an invisible one is a downgrade bought with a large diff.

**The measurement that corrected the argument for it** — and the person who
made it is the person it corrected:

```
commits touching nth_web.py    99 total, 2026-04-02 → 2026-08-15
by month                       Apr 14 · Jul 3 · Aug 82
Aug 1–13, excluding the sprint 60
distinct days with a change     9      ← in a 4.5-month repo
distinct human authors          3
```

hopper's kill argument had been *"a burst from one author, not a trend."* They
measured instead of leaving it as judgement, found **three authors and 60
pre-sprint commits**, and reported that the data corrected *them*.

**This is the part that matters, and it is not a compliment — it is the reason
this deferral is durable.** The kill argument was *right for the wrong reason*,
and a wrong reason survives review in a way a wrong conclusion does not. Had
item 2 been deferred on "one author, one burst", the first person to notice
there are three authors would have found the deferral unfounded and reversed it
— correctly, on the record as written, and wrongly on the merits. The conclusion
survived on a better foundation than the one originally given it:
this file is not edited continuously, it is edited in **campaigns** — intense
multi-day bursts separated by weeks of silence. Decomposition buys nothing on
the ~95% of days nobody touches it, and everything during a campaign.

Hence the dependency at the top: **identity work is a campaign**, so if v9 is
identity, item 2 goes first.

**Meanwhile, do not do nothing** — dijkstra's third option: impose internal
section boundaries within the single file. Most of the review benefit, a
fraction of the risk, and structurally incapable of producing the stale-renderer
regression because there is still one file and one atomic `cp`.

**Trigger conditions to un-defer** (because "when volume proves itself" never
fires on its own) — either one trips it:
1. More than one human contributor active in a 30-day window, **or**
2. A merge conflict in `nth_web.py` costing **more than an hour of judgement**.

The second is the better trigger: it measures pain rather than a proxy for it.
**Judgement is the unit; hunk count is the proxy that misleads** — the v8.1.1
integration resolved 49 mechanical hunks cheaply, and one non-empty-base
conflict cost real thought. Tonight is the baseline.

## Papercut worth one line

`git shortlog -sn --all` reports **eight contributors for a three-person
project**, and there are **eleven** distinct name+email identities behind them,
which is what git actually keys on:

```
gabeayers <contributor-a@example.invalid>      Contributor B <contributor-b@example.invalid>
Contributor A <contributor-a@example.invalid>     Contributor B <owner@example.invalid…>
Contributor A <contributor-a@example.invalid>     repro <owner@example.invalid>
Contributor A <contributor-a@example.invalid>    Repro <owner@example.invalid>
                                      Repro <thereprocase@users.noreply…>
                                      thereprocase <128980993+thereprocase@…>
                                      r <contributor@example.invalid>
```

So any "who wrote this" question currently gets a wrong answer, and one identity
(`r <contributor@example.invalid>`) looks like a misconfigured git client nobody has noticed. A
`.mailmap` is about a dozen lines and fixes it permanently, and nobody will ever
prioritise it on its own.

*(Counted three times tonight and produced three different numbers — six, nine,
eleven — because "name", "name+email", and "shortlog rows" are three different
questions. The figures above are `git shortlog -sn --all | wc -l` = 8 and
`git log --all --format='%an <%ae>' | sort -u | wc -l` = 11. Stated exactly
because a plan that fudges a trivial count invites doubt about the ones that
matter.)*

## Why this plan is worth executing

Every conclusion here has a foundation that was checked, and several of the
foundations were checked *by the person the check embarrassed*:

- hopper killed their own decomposition proposal, then measured and found the
  reasoning behind their own kill argument was false, and corrected it.
- thompson killed their own invite-token proposal.
- coord's ruling on item 3 was reversed by asking whether the repo was public
  rather than by arguing about runners.
- hamilton's sequencing dissent replaced coord's ordering, on a better reason.
- dijkstra's third option replaced a binary keep/kill with something better than
  either side of it.

The value is not the self-correction as a virtue. It is that **a wrong reason
survives review while a wrong conclusion does not** — so a plan whose reasons
were never tested is a plan that gets reversed later by whoever first notices,
and reversed for the wrong reasons. Nothing here survived because someone
asserted it, which is the only property that makes it safe to execute in a month
by someone who wasn't in the room.
